# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project overview

Slide deck for the **2026-05-05 Helsinki Functional Programming meetup**
talk on the [riski5](https://github.com/purefunsolutions/riski5) RISC-V soft
core. Single-page HTML5 deck produced by:

- [Hakyll](https://jaspervdj.be/hakyll/) — Haskell static site generator
  (overkill for one page, but keeps the door open for adding the
  long-form blog post here later)
- [Pandoc](https://pandoc.org/)'s **DZSlides** writer — single
  self-contained `index.html` with native arrow-key navigation,
  inline ~10 KB CSS+JS, no JS framework
- [Graphviz](https://graphviz.org/) `dot` — SoC and pipeline block
  diagrams as `.dot` source, rendered to SVG at build time

Deployed via **GitHub Pages from `master/docs/`** — `docs/` is a
**committed build artifact**, not generated by CI.

## Build commands

```sh
# Dev shell: ghc, cabal, hakyll, pandoc, graphviz, fourmolu, prettier, reuse, python3
nix develop

# Build the deck once into docs/
cabal run site -- build

# Live preview at http://localhost:8000 with auto-rebuild
cabal run site -- watch

# Clean
cabal run site -- clean

# Format (alejandra + fourmolu + prettier + deadnix + statix + shellcheck)
nix fmt

# REUSE + treefmt CI checks
nix flake check
```

## Architecture

**Flake structure**: `flake-parts` with `treefmt-nix` + `flake-root`.
Single host arch `x86_64-linux`. Mirrors the layout of
[`alterade2-flake`](../alterade2-flake/) one-for-one.

**Hakyll site builder**: `site.hs` (~50 LoC). Three rules:

1. Copy `assets/images/**` and `assets/css/**` verbatim
2. Render `assets/diagrams/*.dot` → `*.svg` via `unixFilter "dot"`
3. Pipe `SLIDES.md` → `index.html` via
   `unixFilter "pandoc" [...DZSlides flags...]`

`unixFilter` (calling pandoc CLI directly) is used because Hakyll's
built-in `pandocCompiler` is hardcoded to HTML5 and can't reach the
DZSlides writer.

`Configuration { destinationDirectory = "docs" }` so the build output
lands where GitHub Pages will read it from.

**Slide format — Pandoc DZSlides**:

- `--slide-level=2` → `##` headings become slides
- `#` headings become section-divider title slides
- Lambda corner logo applied via `assets/css/overrides.css` `body::before`
  (fixed-position, every slide automatically)
- `--highlight-style=zenburn` for Haskell code blocks

**Lambda logo**: `assets/images/lambda-logo.png` is copied from
[`~/purefun-front/favicon.png`](https://github.com/purefunsolutions/purefun-front).
Re-render at higher resolution from `assets/lambda.glb` if needed.

## Key conventions

- **Slide source is `SLIDES.md`** — one file, ~38 slides, ~30–40 min talk
- **Built output is `docs/`** — committed alongside source so GitHub
  Pages can serve it directly with no CI step
- **Dual licence** — code under MIT (`site.hs`, `flake.nix`, `nix/*`,
  `cabal.project`, `presentation.cabal`, `fourmolu.yaml`); content
  under CC-BY-4.0 (`SLIDES.md`, `assets/**`, `README.md`, `CLAUDE.md`).
  REUSE.toml encodes the split for `flake.lock`, built artifacts, and
  the borrowed lambda logo.
- **Don't run prettier on `SLIDES.md`** — Pandoc-flavoured Markdown
  has fenced divs / slide-level markers that prettier mangles.
  `nix/treefmt.nix` excludes it.
- **Don't invent Helvetica typography in slide content** — the
  audience reads from a projector. Bullet lists and short prose. The
  speaker fills in the words.

## Common mistakes to avoid

- **Adding npm/JavaScript tooling** — explicitly out of scope.
  `pkgs.revealjs` / Slidev / Marp etc. are eliminated. DZSlides is
  pandoc-bundled; no Node ever enters the picture.
- **Treating `docs/` as ephemeral** — it's a committed build artifact.
  Rebuild before each commit; don't add to `.gitignore`.
- **Splitting the timeline into "weeks"** — the blog post records phase
  dates. Use those.
- **Forgetting SPDX headers** — `nix flake check` will refuse the
  commit. Code gets `MIT`, content gets `CC-BY-4.0`.
- **Editing the lambda logo position in SLIDES.md** — it's a global
  CSS rule in `assets/css/overrides.css`, not per-slide markup.

## Iterating on slide content

The expected workflow for tomorrow's polish loop:

1. Open the live preview: `cabal run site -- watch`
2. Edit `SLIDES.md`
3. Hakyll auto-rebuilds; refresh the browser tab
4. Iterate

For diagram changes, edit `assets/diagrams/*.dot`; the watch loop
re-runs `dot -Tsvg` and Pandoc embeds the SVG in the next rebuild.

When the deck is ready: `git add docs/ && git commit && git push`.
GitHub Pages picks it up within ~60 s.
